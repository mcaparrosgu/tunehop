# Marketing — Paso 4 · Arquitectura de marca (03-arquitectura-marca.md)

> Decide la arquitectura de marca antes de fijar posicionamiento (Paso 5).
> El briefing (00-briefing.md) y la investigación (02-investigacion.md)
> describen un negocio de **un único producto** (TuneHop) sin planes de
> expansión, sub-marcas, líneas paralelas ni portfolio.
>
> Autora: Corita (directora creativa). Fecha: 2026-09-11.

---

## 1. MODELO ELEGIDO

**Arquitectura de marca única** — todo el negocio es TuneHop, y TuneHop es el
producto. No hay marca madre, no hay sub-marcas, no hay casa de marcas.
No aplica portfolio.

**Por qué este modelo y no otro:**
- El briefing §1: "TuneHop es una app web... Emprendedora individual, sin
  equipo ni inversión externa."
- El briefing §2: un único producto (migración Spotify → TIDAL).
- La investigación §5 (Oportunidad) es una sola frase para una sola marca.
- Cualquier arquitectura más compleja (marca madre + sub-marcas, casa de
  marcas) sería complejidad inventada donde no hay negocio que la sostenga.

---

## 2. MAPA DEL PORTFOLIO

No hay portfolio. El mapa es:

```
TuneHop
  └── Producto único: migración de playlists Spotify → TIDAL
```

---

## 3. SISTEMA DE NAMING ENTRE PIEZAS

No aplica (no hay piezas futuras planeadas). Si en el futuro el negocio
creciera y surgiera la necesidad de nombrar módulos, features o líneas
nuevas, se definiría entonces bajo el paraguas de la marca única (ej.
TuneHop Sync, TuneHop Export, TuneHop Insights — convención descriptiva
bajo el nombre principal). Hoy no se decide nada.

---

## 4. CUÁNDO CAMBIAR DE MODELO

Se migraría a **marca madre con sub-marcas** si:
- El negocio lanza un **segundo producto distinto** que resuelve un problema
  distinto para una audiencia distinta (ej. herramienta de analytics para
  artistas, o marketplace de playlists), y necesita su propio nombre para no
  diluir el foco de TuneHop.
- Surge la necesidad de **separar la reputación** del producto principal de
  una línea experimental o B2B (ej. "TuneHop Labs" para features IA, o
  "TuneHop Pro" para DJs/gestión de bibliotecas).

Se migraría a **casa de marcas** (marcas independientes sin vínculo visible)
solo si el negocio se divide en unidades que **no deben asociarse** (ej.
venta de la app a un tercero que la opera por separado). Escenario improbable
y lejano.

**Señal práctica de disparo**: el día que en una reunión de estrategia alguien
diga "esto no encaja bajo TuneHop" y no sea una feature, sino un negocio
distinto. Ese día se abre este documento y se cambia el modelo. Hoy no es
ese día.
