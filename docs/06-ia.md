## 2. QUÉ SÍ PODRÍA NECESITAR IA (pero no en el MVP)

Analicé cada parte del proyecto buscando dónde la IA podría añadir valor. Encontré **un solo punto** donde podría ayudar, y **ninguno** donde sea necesaria.

### 2.1 Fallback de búsqueda: coincidencia difusa (peldaño 1)

**Qué es**: Cuando el ISRC no se encuentra en Deezer, la app busca por título + artista. A veces hay múltiples resultados (covers, versiones en directo, remixes). La IA podría ayudar a elegir la mejor coincidencia.

**Peldaño actual**: 1 — Llamada al modelo con buenas instrucciones.

**Cómo funcionaría**:
```
Input al modelo:
"Busca en Deezer la canción 'Bohemian Rhapsody' de 'Queen'. 
Estos son los resultados: [lista de 5 resultados]. 
Elige el que mejor coincida con: título='Bohemian Rhapsody', 
artista='Queen', duración=355000ms."

Output del modelo:
"El resultado #2 es el mejor: mismo título, mismo artista, 
duración similar (354800ms). Los otros son covers o en vivo."
```

**Por qué peldaño 1 y no más alto**:
- No necesita documentos (no es RAG)
- No necesita pasos encadenados (es una sola decisión)
- No necesita autonomía (siempre decide lo mismo con los mismos datos)
- Es una llamada: datos entrada → decisión → salida

### 2.2 NADA MÁS NECESITA IA

| Parte restante | Por qué no necesita IA |
|---|---|
| OAuth | Protocolo fijo, no hay "criterio" |
| Lectura de playlists | Llamada HTTP exacta |
| Creación de playlists | Llamada HTTP exacta |
| UI (pantallas, botones, progreso) | Componentes estáticos, no "opinan" |
| Gestión de tandas | Bucle con pausa, no necesita criterio |
| Eliminación de datos | Borrar memoria, no necesita IA |
| Errores | Capturar y mostrar, no necesita interpretación |

## 3. JUSTIFICACIÓN DE POR QUÉ EL PELDAÑO 1 ES SUFICIENTE

### Para el fallback de búsqueda (peldaño 1):

**¿Qué se rompe si me quedo en código determinista (sin IA)?**
- Si hay 5 canciones con el mismo nombre, el código elige la primera que encuentre. Puede elegir un cover en vez de la original.
- Consecuencia real: ~5-10% de las canciones podrían no encontrarse o coincidir mal.

**¿Qué gano con IA (peldaño 1)?**
- El modelo compara título, artista y duración para elegir la mejor coincidencia.
- Consecuencia real: sube al ~90-95% de acierto.

**¿Por qué no peldaño 2 (RAG)?**
- No hay documentos que consultar. La información está en los resultados de la API, no en archivos locales.

**¿Por qué no peldaño 3 (workflow)?**
- Es una sola decisión: "¿cuál de estos 5 resultados es el mejor?" No hay pasos encadenados.

**¿Por qué no peldaño 4 (agente)?**
- No hay decisión compleja. Es comparar 3 campos (título, artista, duración). Un agente sería sobredimensionado.

**Veredicto**: Peldaño 1 es el justo. Ni más, ni menos.

## 4. HERRAMIENTAS QUE NECESITA LA IA

### Para el fallback de búsqueda (peldaño 1)

| Herramienta | Qué hace | Lee/Escribe | Reversible | Riesgo |
|---|---|---|---|---|
| **LLM (Claude/GPT)** | Recibe los resultados de la API de Deezer y elige la mejor coincidencia | Solo lee (los resultados) y escribe (la decisión) | Sí, siempre se puede reintentar con otro resultado | **BAJO** — Solo lee y decide. No modifica datos, no borra nada, no crea playlists |

**Cómo se usaría en la app:**

```typescript
// Ejemplo simplificado (no es código final)
async function findBestMatch(results: DeezerTrack[], original: Track): Promise<DeezerTrack> {
  // Si solo hay 1 resultado, devolverlo directamente (sin IA)
  if (results.length === 1) return results[0];
  
  // Si hay varios, preguntar al modelo
  const prompt = `Estos son los resultados de búsqueda para "${original.name}" de "${original.artist}":
${results.map((r, i) => `${i+1}. ${r.title} - ${r.artist.name} (${r.duration}ms)`).join('\n')}

Original: duración ${original.durationMs}ms.
Elige el resultado que mejor coincida (número). Responde SOLO con el número.`;

  const bestIndex = await callLLM(prompt);
  return results[bestIndex - 1];
}
```

## 5. COSTE POR INTERACCIÓN Y AL MES

### Coste del fallback IA (peldaño 1)

| Concepto | Coste estimado |
|---|---|
| Llamada al modelo por canción (fallback) | ~$0.001-0.003 (un tercio de centavo) |
| % de canciones que necesitan fallback | ~10-15% (la mayoría se encuentra por ISRC directo) |
| Volumen previsto (primer año) | ~1.000 migraciones × ~50 canciones × 15% fallback = ~7.500 llamadas |
| **Coste total al mes (estimado)** | **~$0.50-2.00/mes** |

**Veredicto**: El coste es despreciable. Menos de 2€ al mes incluso con miles de usuarios.

### Coste sin IA (código determinista puro)

| Concepto | Coste |
|---|---|
| Búsqueda por nombre+artista (sin IA) | 0€ |
| Precisión estimada | ~85-90% |
| **Coste total al mes** | **0€** |

**Comparativa**: Por ~1€/mes más, la precisión sube de ~85% a ~95%. Merece la pena si el volumen lo justifica.

## 6. QUÉ PASA CUANDO SE EQUIVOCA

### Si el modelo elige mal la canción (fallback)

| Aspecto | Detalle |
|---|---|
| **Consecuencia real** | Se migra una versión incorrecta (cover, remix, en directo) en vez de la original |
| **Cómo lo detectaríamos** | El usuario lo ve en Deezer: la canción suena diferente |
| **Mitigación** | (1) El modelo solo decide cuando hay pocos resultados (≤5). (2) Si hay >5 resultados, se muestra la lista al usuario para que elija. (3) En el resumen se indica "canción migrada con posible variación" |

### Si el modelo se niega a decidir o da un error

| Aspecto | Detalle |
|---|---|
| **Consecuencia real** | La canción queda como "no encontrada" en el resumen |
| **Cómo lo detectaríamos** | El modelo devuelve un error o un resultado inválido |
| **Mitigación** | Si el modelo falla, se usa el primer resultado de la lista (código determinista como fallback del fallback) |

### Si el modelo tiene un coste inesperado

| Aspecto | Detalle |
|---|---|
| **Consecuencia real** | Factura más alta de lo previsto |
| **Cómo lo detectaríamos** | Monitoreo del coste mensual en el dashboard del proveedor de IA |
| **Mitigación** | Límite de llamadas al modelo por migración (ej: máximo 50 llamadas por sesión). Si se supera, se usa código determinista |

## RESUMEN

| Pregunta | Respuesta |
|---|---|
| **¿El MVP necesita IA?** | **NO.** El 100% del MVP se resuelve con código determinista |
| **¿Dónde podría añadir IA?** | En el fallback de búsqueda (cuando ISRC no se encuentra) |
| **¿En qué peldaño?** | 1 — una llamada al modelo con buenas instrucciones |
| **¿Cuánto cuesta?** | ~1-2€/mes (despreciable) |
| **¿Qué pasa si se equivoca?** | Se migra una versión incorrecta. Se detecta en Deezer. Se mitiga con determinismo como fallback |

**Decisión final**: Implementar el MVP **sin IA**. Si en las pruebas reales la precisión del fallback determinista es < 85%, se añade la IA como peldaño 1. No construir IA preventivamente.
